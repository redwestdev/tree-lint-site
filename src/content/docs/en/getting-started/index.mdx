Tree-lint is a file structure linter. The concept is simple: you define your project's structure conventions in a config file, and the tool automatically keeps everything in check. You can run checks locally or right in your CI pipeline.

## Features

- recognizing entities by folder names and their contents;
- checking names, required files, name length, file size, and item count;
- your own rules via `custom` with tailored error messages;
- separating strict (blocking) errors from simple warnings;
- limiting the scanning scope with `roots` and `ignore`;
- CI integration: exits with code `1` when violations are found, and `0` when everything passes.

## Limitations

What Tree-lint doesn't do:
- **code or import analysis** — it only checks file structure and naming conventions;
- **auto-fixing** — it highlights violations, but changes are made by the developer;
- **symbolic links (symlinks)** — they are skipped during scanning.

> Tree-lint is architecture-agnostic. It works equally well for layered or modular structures, legacy codebases, and code-generated projects — anywhere you can define clear file organization rules.
