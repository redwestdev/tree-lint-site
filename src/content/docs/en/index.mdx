## One problem — from agreement to fix

The team agreed: a component is a folder with a `*.tsx` file and `index.ts`, and the folder name is no longer than 20 characters.

```text
src/
└── components/
    └── VeryLongComponentName/   ← 22 characters
        ├── VeryLongComponentName.tsx
        └── index.ts
```

The agreement is written in a config:

```ts
entities: {
  component: {
    matches: {
      type: "directory",
      name: "[A-Z]*",
      children: [
        { type: "file", name: "*.tsx" },
        { type: "file", name: "index.ts" },
      ],
    },
    rules: {
      nameLength: {
        type: "error",
        max: 20,
        message:
          "Component folder name is too long: keep it within 20 characters.",
      },
    },
  },
},
```

Running `tree-lint scan` finds the violation and prints your own message:

```text
src/components/VeryLongComponentName
  ✖ Component folder name is too long: keep it within 20 characters.

Errors: 1, warnings: 0.
```

After renaming to `Icon`, the same command succeeds:

```text
Errors: 0, warnings: 0.

✔ Validation complete successfully!
```

From now on the agreement is checked on every run — locally and in CI, the same way for everyone. The full scenario with the project tree, install commands, and an explanation of every config section is in the [Quick Start](/en/getting-started/quick-start/).

## How to start

1. Install the package as a dev dependency: `npm install -D @redwestdev/tree-lint` (or `pnpm add -D`, `yarn add -D`).
2. Describe a small scope in `tree-lint.config.ts`: one entity and one rule.
3. Run `npx tree-lint scan` and fix what it finds.

Details are on the [Installation](/en/getting-started/installation/) and [Quick Start](/en/getting-started/quick-start/) pages.

## Boundaries and answers to doubts

- **Do I need to change my architecture?** No. The config describes the existing structure, and rules apply only to what you described.
- **Does Tree-lint replace a source code linter?** No. It checks file and folder names, their composition, and the limits you set — not code contents and not imports.
- **Do I have to check the whole project?** No. `roots` and `ignore` limit the scope, and you can start with warnings instead of errors.
- **What does the config give when working with AI?** The assistant can read the same rules, and its output is checked by the same run as your code.
