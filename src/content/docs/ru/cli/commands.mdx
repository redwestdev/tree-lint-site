Tree-lint предлагает две основные команды: `tree-lint init` — создание файла конфигурации, и `tree-lint scan` — запуск проверки.

## `tree-lint init`

Вместо файла вручную можно сгенерировать шаблон конфига командой:

```bash
tree-lint init
```

Команда создаёт файл `tree-lint.config` в текущем каталоге. Поддерживается интерактивный и неинтерактивный режим.

**Интерактивный режим** (TTY-терминал вне CI) - команда запросит недостающие параметры через prompt и предложит подтверждение перед созданием файла. Если выбор не устраивает, можно вернуться и указать параметры заново.

**Неинтерактивный режим** (CI) - все параметры должны быть переданы явно через флаги:

```bash
tree-lint init --format ts --type deep-tree
```

| Флаг                      | Возможные значения | Описание                  |
| ------------------------- | ------------------ | ------------------------- |
| `-f`, `--format <format>` | ts, js, json, yaml | Формат файла конфигурации |
| `-t`, `--type <type>`     | default, deep-tree | Шаблон конфигурации       |

### Шаблоны

Доступно два шаблона:

- **default** — типовые сущности (`component`, `hook`, `page`, `util`, `service`, `context`, `typeFile`) со своими слоями и примером правил для дочерних элементов с `_matches`;
- **deep-tree** — всё из `default` плюс секция `groups` и примеры проверок `custom()` для сущностей.

Оба шаблона — отправная точка: замените примеры сущностей на собственную архитектуру.

## `tree-lint scan`

Сканирование запускается командой `tree-lint scan` — так, как показано в [Быстром старте](/ru/getting-started/quick-start/). Дополнительные флаги команды:

| Флаг                              | Описание                                                                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `[path]`                          | Каталог для сканирования вместо текущего. Корни `roots` из конфига разрешаются относительно него, а сам конфиг по-прежнему ищется от текущего каталога вверх             |
| `-t`, `--tree-output [file]`      | Экспортировать сырую структуру файловой системы в JSON-файл. Без аргумента пишет `.project-tree.json` рядом с каталогом сканирования                                     |
| `-a`, `--annotated-output [file]` | Экспортировать обработанное дерево (с распознанными слоями, сущностями и группами) в JSON-файл. Без аргумента пишет `.entities-tree.json` рядом с каталогом сканирования |
| `-v`, `--vitals`                  | Показать метрики производительности движка (CPU, память и эффективность I/O)                                                                                             |
| `-p`, `--print-tree`              | Вывести проанализированную структуру проекта прямо в терминал                                                                                                            |
| `-c`, `--config-path [path]`      | Путь к файлу конфигурации. По умолчанию конфиг ищется от текущего каталога вверх                                                                                         |
| `-g`, `--group-by <type>`         | Изменить группировку результатов сканирования (по умолчанию "path")                                                                                                      |

> Короткий флаг `-t` означает разное в `init` (`--type`) и `scan` (`--tree-output`). В скриптах и CI лучше использовать длинные имена флагов, чтобы избежать путаницы.

### Группировка результатов: `--group-by`

Возможные значения для `--group-by` на примере сценария из [Быстрого старта](/ru/getting-started/quick-start/):

- `path` (по умолчанию) - группировка по пути в файловой системе:

  ```text
  src/hooks/useThisHookNameIsDefinitelyTooLong.ts
    ⚠ Name length is outside the allowed character limits

  src/hooks/use_foo.ts
    ✖ Хук: use + camelCase.
  ```

- `severity` - группировка по уровню (`error`, `warning`):

  ```text
  ✖ ERRORS:
    Хук: use + camelCase. - src/hooks/use_foo.ts

  ⚠ WARNINGS:
    Name length is outside the allowed character limits - src/hooks/useThisHookNameIsDefinitelyTooLong.ts
  ```

- `rule` - группировка по тексту нарушенного правила:

  ```text
  Name length is outside the allowed character limits
    ⚠ src/hooks/useThisHookNameIsDefinitelyTooLong.ts

  Хук: use + camelCase.
    ✖ src/hooks/use_foo.ts
  ```
