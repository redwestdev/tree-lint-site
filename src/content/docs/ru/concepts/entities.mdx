**Сущность** — именованный тип узлов проекта. В секции `entities` конфига поле `matches` задаёт, какие узлы распознавать, а `rules` — какие проверки применять к распознанным узлам.

Сущностью может быть отдельный файл, например файл-хук или файл-модель, либо папка, например компонент или страница. Соглашения о содержимом папок можно проверять правилами `rules`.

Сущность может иметь сложную структуру и глубокую вложенность.

> Внутри сущности можно описывать вложенные сущности — например, собственные стили, хуки или подкомпоненты.

## Примеры структуры проекта и конфигурации

Слой задаёт контекст, в котором Tree-lint ищет сущность. Подробнее о слоях — в разделе [Слои](/ru/concepts/layers/).

      matches: { type: 'file', name: 'use*' },

      matches: { type: 'directory', name: '[A-Z]*' },

    },
  },

  layers: {
    components: { entities: ['component'] },
    helpers: { entities: ['helper'] },

  <TabItem label='Вложеная структура'>
    Страницы распознаются по суффиксу `Page`, компоненты — по имени папки, а файлы-хуки, иконки, изображения, helper- и

    требуют их наличия. Названия слоёв действуют на любой глубине внутри `roots`, не только в `CatalogPage/`.

В базовом примере `useCounter.ts` распознаётся как `hook`, папки компонентов — как `component`, а CSS-модули в корне этих папок — как вложенные сущности `style`. Обычные файлы `.ts` в слое `functions` распознаются как `function`, файлы с окончаниями `.model.ts` и `.util.ts` — как соответствующие сущности, а файлы `*Route.ts` — как `route`.

Это примеры, а не обязательная структура проекта: сущности и слои можно настроить под соглашения проекта.

Распознавание всегда идёт раньше проверки: если узел не совпал с `matches`, правила `rules` этой сущности к нему не применяются.
