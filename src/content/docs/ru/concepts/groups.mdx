**Группа** позволяет применять правила к обычной папке, не объявляя её сущностью. Группа создавалсь с целью объединять по смыслу сущности, но для них не нужны отдельный тип сущности или слой.

У групп, слоёв и сущностей разные задачи:

- **Слой** — папка с именем, указанным в `layers`; он задаёт, какие сущности искать внутри.
- **Сущность** — объявленный в `entities` тип файлов или папок. Чтобы распознаваться, сущность связывают со слоем или объявляют вложенной сущностью.
- **Группа** — обычная папка, к которой применяются критерии сопоставления и правила. Её не нужно объявлять в `entities` или привязывать к слою.

## Когда использовать группы

Группы удобны, чтобы разделить сущности по папкам, не создавая для каждой такой папки отдельную архитектурную сущность. По умолчанию группы работаю�� автоматически без секции `groups`, а при необходимости к ним можно добавить правила:

Группа применяется только к _обычной папке_ — той, которая не распознана как слой или сущность.
В ней должен быть хотя бы один распознанный дочерний элемент: слой, сущность или другая группа. Папка, содержащая только нераспознанные файлы, группой не станет.
Поэтому группа не заменяет сущность там, где нужен отдельный тип с собственным описанием и связью со слоем.

## Сопоставление и правила

В конфигурации `groups` — один объект. Необязательное поле `matches` задаёт критерии сопоставления: `name` — шаблон имени папки, а `children` — список дочерних элементов, которые должны в ней найтись. Поле `rules` задаёт проверки самой папки:

<ArchSplit variant='columns' treeLabel='Структура проекта' configLabel='Конфигурация'>
  <Fragment slot='tree'>

```tree
src/
└── components/        ← слой
    └── buttons/       ← группа
        ├── IconButton/  ← сущность
        ├── TextButton/  ← сущность
        └── index.ts
```

  </Fragment>
  <Fragment slot='config'>

```ts title="tree-lint.config.ts"
groups: {
  matches: {
    name: '[a-z]*',
    children: [{ type: 'file', name: 'index.ts' }],
  },
  rules: { nameLength: { type: 'warning', max: 20 } },
},
```

  </Fragment>
</ArchSplit>

В примере папка `buttons` соответствует шаблону имени и содержит обязательный файл `index.ts`.
В ней также есть распознанные дочерние сущности

`IconButton` и `TextButton` — без хотя бы одного распознанного дочернего элемента группа не применяется.

`rules` проверяет длину имени папки; лишние дочерние элементы не мешают сопоставлению.
Если заданы критерии `matches`, но совпадение неполное, Tree-lint выводит предупреждение распознавания.

Если отдельные критерии сопоставления не нужны, `matches` можно опустить: правила будут применяться к подходящим обычным папкам без отбора по имени или составу.
Как и для других групп, у папки должен быть хотя бы один распознанный дочерний элемент.

Вкладки ниже показывают примеры только с `groups.rules`; предполагается, что сущности и слои уже настроены.
