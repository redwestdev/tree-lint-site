Tree-lint следит за порядком в файлах и папках проекта.
Один раз описываются правила в конфиге, а линтер проверяет их при каждом запуске — локально и в CI.

## Какие задачи решает

- **Контроль за файловой структурой** — каждая сущность, модуль или слой содержит только то, что описано правилами.
- **Экономия времени на ревью** — рутинные споры о путях и именах файлов уходят в автоматическую проверку в CI.
- **Предсказуемый рост проекта** — единый конфиг удерживает структуру от хаоса, даже когда команда и кодовая база стремительно растут.
- **Рамки для ИИ-ассистентов** — линтер ловит галлюцинации нейросетей и проверяет, что сгенерированный код лежит на своем месте.
- **Быстрый онбординг** — понятные подсказки об ошибках помогают новичкам сразу писать по стандартам проекта без чтения длинных гайдов.

## Что умеет

- **Распознавать архитектуру** — находит сущности (`entities`), слои (`layers`) и группы (`groups`) по шаблонам и структуре.
- **Проверять файловые правила** — контролирует имена файлов и папок, регистр, состав содержимого, глубину вложенности, размеры и количество элементов.
- **Задавать произвольные проверки** — позволяет описывать собственные правила через `custom` с понятными сообщениями об ошибках.
- **Разделять уровни важности** — поддерживает блокирующие ошибки (`error`) и предупреждения (`warn`).
- **Ограничивать область проверки** — настраивает пути для сканирования и исключения через `roots` и `ignore`.
- **Встраиваться в CI** — завершает процесс с кодом `1` при обнаружении ошибок и с кодом `0` при успешной проверке.

## Чего Tree-lint не делает

- **Не анализирует код внутри файлов** — не проверяет AST, типы, импорты и экспорты, а работает только со структурой файлов и папок.
- **Не исправляет нарушения автоматически** — показывает, что нужно изменить, а решение принимает разработчик.
- **Не обходит символические ссылки** — пропускает их при сканировании.

## Конфигурация

Конфигурация состоит из:

```ts
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['src'], // директории для сканирования
  ignore: ['node_modules', 'dist'], // что пропускать
  entities: {}, // сущности
  layers: {}, // слои
  groups: {}, // группы (необязательно)
});
```

- `roots` и `ignore` — область сканирования: подробности на странице [Корни и исключения](/ru/configuration/roots-ignore/);
- `entities` — сущности: типы узлов, которые Tree-lint распознаёт и проверяет;
- `layers` — слои: папки, внутри которых ищутся сущности;
- `groups` — группы: правила для «обычных» папок по паттерну имени.

Поддерживаемые форматы файла конфигурации — на странице [Форматы конфигурации](/ru/configuration/config-formats/).
