**Слой** — папка, имя которой точно совпадает с ключом в секции `layers`. Tree-lint распознаёт слои на любой глубине внутри `roots`, кроме папок, уже распознанных как сущности.

Слой задаёт, какие сущности искать внутри подходящих папок.

## Пример структуры проекта и конфигурации

Имена папок-слоёв должны точно совпадать с ключами в `layers`, а значения `entities` — с именами сущностей, объявленных в конфиге. Например:

## Как проектировать слои

Слои помогают группировать сущности по их роли в проекте. Обычно слой объединяет один тип сущностей:

- `components` — `component`;
- `functions` — `function`;
- `routes` — `route`.

Это рекомендация, а не ограничение: один слой может включать несколько близких по роли типов, например `util`, `function` и `helper` в слое `functions`. Лучше не смешивать в одном слое сущности, не связанные по смыслу, например классы, стили, функции и компоненты.

## Где распознаются сущности

Сейчас Tree-lint распознаёт сущности внутри слоёв или внутри другой сущности — подробнее о [вложенных сущностях](/ru/matching/entities/#вложенные-сущности). Сущность, не указанная ни в одном слое и не объявленная вложенной, не распознаётся.

В планах — добавить способы определять сущности без участия слоя. Это будущие возможности, а не текущее поведение; распознавание через слои останется одним из простых и понятных способов.

## Правила для самого слоя

В `layers.*.rules` задаются правила для самой папки-слоя, а не для сущностей внутри неё. Например, так можно проверять имя слоя или количество его дочерних элементов. Список правил — на странице [Валидация слоя](/ru/validation/layers/).

```ts
layers: {
  components: {
    entities: ['component'],
    rules: { isEmpty: { type: 'warning' } },
  },
},
```
