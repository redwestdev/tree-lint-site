Каждый запуск Tree-lint проходит по одному дереву несколько раз: сначала находит слои, затем распознаёт сущности в их границах, определяет подходящие группы и только затем проверяет правила.

> Tree-lint валидирует только то что смог опознать.

## Пример: небольшой проект

Возьмём небольшой проект с двумя слоями. Конфигурация распознаёт компоненты по расширению `.tsx`, а хуки — по имени `use...` и расширению `.ts`:

<ArchSplit variant='slide' treeLabel='Структура проекта' configLabel='Конфигурация'>
  <Fragment slot='tree'>

```tree
src/
├── components/      ← слой
│   ├── buttons/     ← группа
│   │   └── PrimaryButton.tsx  ← сущность
│   └── fields/      ← группа
│       └── TextField.tsx      ← сущность
└── hooks/           ← слой
    └── useCounter.ts          ← сущность
```

  </Fragment>
  <Fragment slot='config'>

```ts title="tree-lint.config.ts"
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['src'],
  entities: {
    component: { matches: { type: 'file', name: '*.tsx' } },
    hook: { matches: { type: 'file', name: 'use*.ts' } },
  },
  layers: {
    components: { entities: ['component'] },
    hooks: { entities: ['hook'] },
  },
  groups: { name: '*' },
});
```

  </Fragment>
</ArchSplit>

С этими настройками `PrimaryButton.tsx` и `TextField.tsx` распознаются как компоненты, `useCounter.ts` — как хук, а подходящие папки `buttons` и `fields` — как группы.

## Этапы обхода

<RecognitionFlow />

1. **Поиск слоёв.** Tree-lint обходит область `roots` с учётом настроек `ignore` и обработки символических ссылок и ищет папки, имя которых совпадает с ключом `layers`. В примере это `components` и `hooks`. Слой задаёт границу, внутри которой ищутся только указанные для него типы сущностей.
2. **Распознавание сущностей.** Внутри найденных слоёв Tree-lint проверяет узлы по `matches` сущностей, перечисленных в конфигурации слоя. Поэтому `PrimaryButton.tsx` и `TextField.tsx` ищутся как компоненты в слое `components`, а `useCounter.ts` — как хук в слое `hooks`.
3. **Определение групп.** Обычная папка становится группой,
   только если между слоем и группой есть дополнительные папки. Дополнительные настройки matches у группы позволяют явно определять группы в других местах.

4. **Проверка правил и отчёт.** При финальном обходе `rules` применяются к распознанным слоям, сущностям и группам. Результаты проверки формируют отчёт.

## Ошибки и предупреждения

В итоговом отчёте Tree-lint разделяет два уровня замечаний:

- **Ошибка (`error`)** — блокирует успешный результат: `tree-lint scan` завершается с кодом `1`, а CI падает. Замечание выводится как `✖ error`.
- **Предупреждение (`warning`)** — не блокирует результат: команда завершается с кодом `0`, замечание выводится как `⚠ warning`, но разработчику его видно.

Правило со значением `off` отключает проверку; ошибку можно «смягчить» до предупреждения, установив `type: 'warning'` для конкретного правила.
