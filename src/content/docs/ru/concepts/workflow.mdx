Каждый запуск Tree-lint проходит один и тот же путь: сканирование, распознавание сущностей и применение правил. Разобранный пример ниже показывает, что происходит на каждом шаге.

## Общий поток

<RecognitionFlow />

1. **Сканирование** — Tree-lint обходит `roots`, пропускает `ignore` и символические ссылки.
2. **Распознавание** — для каждой папки определяется её роль: слой (по имени), сущность (по `matches`), папка группы, обычная папка или файл.
3. **Проверка правилами** — для каждого распознанного узла применяются `rules`: сущности, слоя и группы.
4. **Отчёт** — нарушения выводятся как ошибки и предупреждения.

## Пример: небольшой проект

Возьмём проект с тремя папками:

```
src/
├── components/       → слой components
├── hooks/            → слой hooks
└── utils/            → обычная папка
```

Проследим путь каждой папки.

### `src/components` — слой

1. Имя `components` совпадает с ключом секции `layers` → папка распознана как **слой**.
2. Внутри слоя Tree-lint ищет сущности, перечисленные в `entities` слоя.
3. Применяются правила самого слоя (`rules` слоя), если они заданы.

### `src/hooks` — слой с распознаванием сущности

1. Имя `hooks` совпадает с ключом `layers` → папка распознана как **слой**.
2. Внутри слоя файл `useCounter.ts` совпадает с `matches` сущности `hook` → файл распознан как **сущность**.
3. К сущности применяются её правила: например, `nameLength`.

### `src/utils` — обычная папка

1. Имя не совпадает ни с одним слоем → слой не найден.
2. Состав папки не совпадает с `matches` ни одной сущности → сущность не распознана.
3. Папка сопоставляется с `groups` (если группа задана) — иначе она просто игнорируется линтером.

## Ошибки и предупреждения

Tree-lint разделяет два уровня замечаний:

- **Ошибка (`error`)** — блокирует результат: `tree-lint scan` завершается с кодом `1`, а CI падает. Замечание выводится как `✖ error`.
- **Предупреждение (`warning`)** — не блокирует: команда завершается с кодом `0`, замечание выводится как `⚠ warning`, но разработчику его видно.

Правило со значением `off` отключает проверку; ошибки можно «смягчить» до предупреждений, установив `type: 'warning'` для конкретного правила.
