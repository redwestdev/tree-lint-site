---
title: Корни и исключения
description: 'Как ограничить область сканирования через roots и ignore, в том числе при инкрементальном рефакторинге легаси-проектов.'
---

Область сканирования задаётся двумя секциями конфига: `roots` и `ignore`. С их помощью проверку можно ограничить только той частью проекта, о которой команда уже договорилась, — например, при постепенном внедрении в существующий проект.

## `roots`

- `roots` — директории, внутри которых Tree-lint сканирует. Каждый корень сканируется независимо. По умолчанию используется текущий каталог.
- Корни — это конкретные пути, а не glob-паттерны, и они разрешаются относительно каталога, из которого запущен `scan`.
- Пути за пределами каталога запуска игнорируются с предупреждением `Access denied`.

## `ignore`

- `ignore` — список micromatch-паттернов. Файлы и папки, совпавшие с паттерном, исключаются из сканирования.
- Паттерн сопоставляется с полным путём относительно проекта, например `"**/*.test.ts"` или `"**/__mocks__"`.

## Внедрение в легаси-проект

Tree-lint не требует проверять весь проект сразу: область сканирования и строгость правил настраиваются постепенно. Это позволяет внедрить линтер в существующую кодовую базу, не останавливая разработку. Стратегия из четырёх шагов:

1. **Начните с одной директории.** Ограничьте `roots` той частью проекта, по которой соглашение уже принято, — например, новым модулем или папкой компонентов.
2. **Исключите старый код.** Паттерны `ignore` скрывают ту часть кодовой базы, которую пока не трогаем, — она не блокирует проверку.
3. **Начните с предупреждений.** Задайте правилам `type: "warning"` — нарушения видны в отчёте, но не валят запуск и CI.
4. **Переводите предупреждения в ошибки.** По мере наведения порядка меняйте `warning` на `error` — договорённость становится обязательной.

Так Tree-lint сначала оценивает, где файловая структура расходится с целевой моделью, а затем закрепляет соглашение по частям.

## Монорепо

**Задача.** Проверять каждый пакет независимо, не сканируя весь репозиторий целиком.

В Tree-lint 0.0.5 один конфиг — это один набор правил, без отдельных правил для каждого корня. Для монорепо есть два рабочих варианта.

### Вариант A: общий конфиг в корне репозитория

```typescript
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['packages/ui/src', 'packages/core/src'],
  ignore: ['node_modules', 'dist'],

  entities: {
    component: {
      matches: {
        type: 'directory',
        name: '[A-Z]*',
        children: [
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: 'index.ts' },
        ],
      },
      rules: {
        nameLength: {
          type: 'error',
          max: 20,
          message:
            'Имя папки компонента слишком длинное: уложитесь в 20 символов.',
        },
      },
    },
  },

  layers: {
    components: { entities: ['component'] },
  },
});
```

Запуск из корня репозитория:

```
$ tree-lint scan

Will scan the following paths:
  packages/core/src
  packages/ui/src

packages/ui/src/components/VeryLongComponentName
  ✖ Имя папки компонента слишком длинное: уложитесь в 20 символов.

Errors: 1, warnings: 0.
✖ Validation failed.
```

Одни и те же правила применяются ко всем перечисленным корням.

### Вариант B: свой конфиг в каждом пакете

Если правила у пакетов разные, положите `tree-lint.config.ts` в каждый пакет и указывайте в нём локальные корни:

```typescript
// packages/ui/tree-lint.config.ts
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['src'], // относительно каталога, из которого запущен scan
  ignore: ['node_modules', 'dist'],
  // ...entities и layers, как выше
});
```

Запуск из каталога пакета:

```
$ cd packages/ui && tree-lint scan
```

Tree-lint подхватит ближайший конфиг, поднимаясь от текущего каталога вверх.

**Границы вариантов.** `roots` — это конкретные пути, а не glob-паттерны, и они разрешаются относительно каталога, из которого запущен `scan`. Пути за пределами каталога запуска игнорируются с предупреждением `Access denied`. Если запустить команду из `packages/ui` с конфигом варианта A, корни `packages/ui/src` будут искаться внутри `packages/ui` — поэтому в варианте B корни локальные.
