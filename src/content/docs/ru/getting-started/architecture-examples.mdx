Каждый рецепт — это задача, дерево проекта, полный конфиг и результат запуска. Все конфиги проверены на Tree-lint 0.0.5.

Правила в рецептах не повторяют шаблоны из `matches`: совпадение имени уже проверяется при распознавании, а `rules` добавляют то, чего распознавание не умеет — размер, длину имени, состав и собственные условия. Подробности — в [Концепциях](/ru/getting-started/concepts/).

## Компоненты и хуки

**Задача.** Компонент не должен раздуваться: файл `*.tsx` — не длиннее 200 строк, хук — не длиннее 80 строк. Папка компонента обязана содержать `*.tsx` и `index.ts`.

**Дерево:**

```
src/
├── components/
│   ├── Button/
│   │   ├── Button.tsx      ← 250 строк
│   │   └── index.ts
│   └── Icon/
│       ├── Icon.tsx
│       └── index.ts
└── hooks/
    └── useDebounce.ts      ← 90 строк
```

**Конфиг:**

```typescript
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['src'],
  ignore: ['node_modules', 'dist'],

  entities: {
    component: {
      matches: {
        type: 'directory',
        name: '[A-Z]*',
        children: [
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: 'index.ts' },
        ],
      },
      rules: {
        children: [
          {
            _matches: { type: 'file', name: '*.tsx' },
            lineCount: { type: 'error', max: 200 },
          },
        ],
      },
    },

    hook: {
      matches: { type: 'file', name: 'use*.{ts,tsx}' },
      rules: { lineCount: { type: 'warning', max: 80 } },
    },
  },

  layers: {
    components: { entities: ['component'] },
    hooks: { entities: ['hook'] },
  },
});
```

**Что найдёт запуск:**

```
src/components/Button/Button.tsx
  ✖ Line count in this file violates the maximum or minimum threshold

src/hooks/useDebounce.ts
  ⚠ Line count in this file violates the maximum or minimum threshold

Errors: 1, warnings: 1.
✖ Validation failed.
```

Ошибка блокирует запуск (код выхода 1). Исправление: разбить `Button.tsx` на несколько файлов — и проверка проходит с кодом выхода 0.

**Границы этого рецепта:**

- Распознаётся только компонент с полным составом детей. Папка без `index.ts` или пустая даёт предупреждение "It looks as component, but composition of child elements is invalid." — правила на неё не применяются, поэтому `isEmpty` для пустой папки здесь не сработает.
- `use*.{ts,tsx}` распознаёт хуки только внутри папки `hooks` — слой ограничивает зону действия сущностей.

## Feature-Sliced Design (FSD)

**Задача.** Закрепить файловые соглашения FSD: страницы, фичи и виджеты — отдельные типы папок с обязательным составом, а имя виджета — не длиннее 20 символов.

**Дерево:**

```
src/
├── pages/
│   └── profile/
│       ├── ProfilePage.tsx             ← 180 строк
│       └── profile.module.css
├── features/
│   └── cart/
│       ├── cart.tsx
│       └── index.ts
├── widgets/
│   └── ProductCardWithVeryLongName/    ← 25 символов
│       ├── ProductCardWithVeryLongName.tsx
│       └── index.ts
├── entities/
│   └── user.model.ts
└── shared/
    └── lib/
        └── format.lib.ts
```

**Конфиг:**

```typescript
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['src'],
  ignore: ['node_modules', 'dist'],

  entities: {
    page: {
      matches: {
        type: 'directory',
        name: '[a-z]*',
        children: [
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: '*.module.css' },
        ],
      },
      rules: {
        children: [
          {
            _matches: { type: 'file', name: '*.tsx' },
            lineCount: { type: 'warning', max: 150 },
          },
        ],
      },
    },

    feature: {
      matches: {
        type: 'directory',
        name: '[a-z]*',
        children: [
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: 'index.ts' },
        ],
      },
    },

    widget: {
      matches: {
        type: 'directory',
        name: '[A-Z]*',
        children: [
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: 'index.ts' },
        ],
      },
      rules: {
        nameLength: {
          type: 'error',
          max: 20,
          message: 'Имя виджета слишком длинное: уложитесь в 20 символов.',
        },
      },
    },

    model: { matches: { type: 'file', name: '*.model.ts' } },
    lib: { matches: { type: 'file', name: '*.lib.ts' } },
  },

  layers: {
    pages: { entities: ['page'] },
    features: { entities: ['feature'] },
    widgets: { entities: ['widget'] },
    entities: { entities: ['model'] },
    shared: { entities: ['lib'] },
  },
});
```

**Что найдёт запуск:**

```
src/pages/profile/ProfilePage.tsx
  ⚠ Line count in this file violates the maximum or minimum threshold

src/widgets/ProductCardWithVeryLongName
  ✖ Имя виджета слишком длинное: уложитесь в 20 символов.

Errors: 1, warnings: 1.
✖ Validation failed.
```

**Границы этого рецепта.** Это адаптируемый пример файловых соглашений в духе FSD, а не полная проверка FSD: Tree-lint не анализирует импорты, не проверяет, что слой не зависит от вышележащих слоёв, и не следит за публичным API. Имена и состав детей в `matches` подстраивайте под структуру своего проекта.

## Монорепо

**Задача.** Проверять каждый пакет независимо, не сканируя весь репозиторий целиком.

В Tree-lint 0.0.5 один конфиг — это один набор правил, без отдельных правил для каждого корня. Для монорепо есть два рабочих варианта.

### Вариант A: общий конфиг в корне репозитория

```typescript
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['packages/ui/src', 'packages/core/src'],
  ignore: ['node_modules', 'dist'],

  entities: {
    component: {
      matches: {
        type: 'directory',
        name: '[A-Z]*',
        children: [
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: 'index.ts' },
        ],
      },
      rules: {
        nameLength: {
          type: 'error',
          max: 20,
          message:
            'Имя папки компонента слишком длинное: уложитесь в 20 символов.',
        },
      },
    },
  },

  layers: {
    components: { entities: ['component'] },
  },
});
```

Запуск из корня репозитория:

```
$ tree-lint scan

Will scan the following paths:
  packages/core/src
  packages/ui/src

packages/ui/src/components/VeryLongComponentName
  ✖ Имя папки компонента слишком длинное: уложитесь в 20 символов.

Errors: 1, warnings: 0.
✖ Validation failed.
```

Одни и те же правила применяются ко всем перечисленным корням.

### Вариант B: свой конфиг в каждом пакете

Если правила у пакетов разные, положите `tree-lint.config.ts` в каждый пакет и указывайте в нём локальные корни:

```typescript
// packages/ui/tree-lint.config.ts
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['src'], // относительно каталога, из которого запущен scan
  ignore: ['node_modules', 'dist'],
  // ...entities и layers, как выше
});
```

Запуск из каталога пакета:

```
$ cd packages/ui && tree-lint scan
```

Tree-lint подхватит ближайший конфиг, поднимаясь от текущего каталога вверх.

**Границы вариантов.** `roots` — это конкретные пути, а не glob-паттерны, и они разрешаются относительно каталога, из которого запущен `scan`. Пути за пределами каталога запуска игнорируются с предупреждением `Access denied`. Если запустить команду из `packages/ui` с конфигом варианта A, корни `packages/ui/src` будут искаться внутри `packages/ui` — поэтому в варианте B корни локальные.

## Документация и переводы

**Задача.** В папке документации — только файлы `.md` и `.mdx`, а файлы переводов называются двумя строчными буквами (`en.json`, `ru.json`). Рецепт составлен по мотивам конфига самого сайта Tree-lint.

**Дерево:**

```
content/
├── docs/
│   ├── getting-started.mdx
│   ├── api.md
│   └── README.txt              ← лишний формат
└── i18n/
    ├── ru.json
    ├── en.json
    └── uk-UA.json              ← имя не по правилу
```

**Конфиг:**

```typescript
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['content'],
  ignore: ['node_modules', 'dist'],

  entities: {
    doc: { matches: { type: 'file', name: '*.{md,mdx}' } },
    translation: { matches: { type: 'file', name: '[a-z][a-z].json' } },
  },

  layers: {
    docs: {
      entities: ['doc'],
      rules: {
        custom: {
          type: 'error',
          message: 'В папке документации могут лежать только файлы .md и .mdx.',
          callback: (node) =>
            node.children.every(
              (child) => child.extension === 'md' || child.extension === 'mdx'
            ),
        },
      },
    },
    i18n: {
      entities: ['translation'],
      rules: {
        custom: {
          type: 'error',
          message:
            'Файл перевода должен называться двумя строчными буквами: en.json, ru.json.',
          callback: (node) =>
            node.children.every((child) =>
              /^[a-z][a-z]\.json$/.test(child.name)
            ),
        },
      },
    },
  },
});
```

**Что найдёт запуск:**

```
content/docs
  ✖ В папке документации могут лежать только файлы .md и .mdx.

content/i18n
  ✖ Файл перевода должен называться двумя строчными буквами: en.json, ru.json.

Errors: 2, warnings: 0.
✖ Validation failed.
```

Исправление: удалить `README.txt` и переименовать `uk-UA.json` в `uk.json` — проверка проходит.

**Почему здесь нужен `custom`.** Сущность `doc` умеет распознавать только правильные файлы: `README.txt` под неё не подпадает, и без проверки на слое он остался бы незамеченным. Правило `custom` на слое видит всех детей папки — и подходящих, и лишних. Не забудьте `type: "error"` — без него Tree-lint 0.0.5 завершается внутренней ошибкой. Подробнее — в [Использовании проверки custom](/ru/rules/custom-usage/).
