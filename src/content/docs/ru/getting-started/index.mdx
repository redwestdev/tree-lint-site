Tree-lint — детерминированный линтер файловой структуры. Вы описываете в конфиге свои соглашения о файлах и папках, а Tree-lint проверяет их при каждом запуске — локально и в CI.

## Какие задачи решает

- **Борьба с хаосом в структуре** — соглашения о файлах и папках превращаются в исполняемые правила, которые проверяются при каждом запуске, а не на глаз при ревью.
- **Подготовка контракта для ИИ** — единый файл правил, который может прочитать ИИ-ассистент и которым проверяется результат его работы.
- **Ускорение онбординга** — новый разработчик видит принятую структуру и нарушения сразу, без пересказа «как у нас принято».

## Что умеет

- распознавать сущности по имени и составу папки;
- проверять имена, обязательный состав папки, длину имени, размер и число элементов;
- задавать собственные проверки через `custom` с любым сообщением;
- разделять блокирующие ошибки и предупреждения;
- ограничивать область проверки через `roots` и `ignore`;
- встраиваться в CI: при ошибках команда завершается с кодом `1`, без ошибок — с кодом `0`.

## Чего не обещает

- не разбирает содержимое кода и не проверяет импорты — только файловую структуру;
- не исправляет структуру автоматически — показывает нарушение, а исправляет его разработчик;
- не поддерживает символические ссылки — они пропускаются при сканировании.

> Tree-lint не привязан к конкретной архитектуре. Подойдёт слоистым и модульным структурам, легаси и проектам с генерацией кода — везде, где можно описать соглашение о файлах и папках.
