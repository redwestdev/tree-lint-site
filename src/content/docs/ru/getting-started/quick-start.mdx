Этот раздел — один сквозной пример: от установки до исправленной ошибки. Все команды и конфиг относятся к одному и тому же маленькому проекту, поэтому шаги можно проходить по порядку и повторять на своём проекте.

Представим, что команда договорилась о структуре компонентов:

- каждый компонент лежит в собственной папке внутри `src/components`;
- имя папки начинается с заглавной буквы и не длиннее 20 символов;
- внутри папки обязательно есть файл с расширением `.tsx` и файл `index.ts`.

Папка `VeryLongComponentName` нарушает второе правило: в имени 22 символа.

Начнём с такого маленького проекта:

```
src/
└── components/
    └── VeryLongComponentName/
        ├── VeryLongComponentName.tsx
        └── index.ts
```

Создайте его в папке своего учебного проекта — например, `my-tree-lint-demo`, — или возьмите уже существующий проект с подобной структурой. Далее все шаги выполняются внутри этого проекта.

## 2. Опишите договорённости в конфиге

Создайте в корне проекта файл `tree-lint.config.ts`:

```ts
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  roots: ['src'], // где сканировать
  ignore: ['node_modules', 'dist'], // что пропускать

  entities: {
    component: {
      matches: {
        type: 'directory',
        name: '[A-Z]*', // имя папки начинается с заглавной буквы
        children: [
          // обязательный состав папки компонента
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: 'index.ts' },
        ],
      },
      rules: {
        nameLength: {
          type: 'error',
          max: 20,
          message:
            'Имя папки компонента слишком длинное: уложитесь в 20 символов.',
        },
      },
    },
  },

  layers: {
    components: {
      entities: ['component'], // искать компоненты внутри папок components
    },
  },
});
```

Что здесь написано:

- `matches` — как **распознать** компонент: папка, имя которой начинается с заглавной буквы, с обязательным составом из `.tsx`-файла и `index.ts`. Распознавание само по себе не выводит ошибок — оно только решает, где применять правила.
- `rules.nameLength` — **проверка** для каждой распознанной папки: длина имени не больше 20 символов. `message` — собственный текст ошибки на русском.
- `layers.components` — компоненты распознаются только внутри папок с именем `components` на любой глубине внутри `roots`.

Как эти секции работают вместе, подробно разобрано в [Основных понятиях](/ru/getting-started/concepts/).

## 3. Запустите проверку

<Tabs syncKey='pkg'>
  <TabItem label='npm'>```bash npx tree-lint scan ```</TabItem>
  <TabItem label='pnpm'>```bash pnpm exec tree-lint scan ```</TabItem>
  <TabItem label='yarn'>```bash yarn tree-lint scan ```</TabItem>
</Tabs>

В выводе — найденное нарушение:

```text
src/components/VeryLongComponentName
  ✖ Имя папки компонента слишком длинное: уложитесь в 20 символов.

Errors: 1, warnings: 0.

✖ Validation failed.
```

Что важно в этом выводе:

- нарушение относится к папке `VeryLongComponentName` — сканирование идёт от `src`;
- текст ошибки — ваш собственный `message`, а не служебное сообщение;
- при наличии ошибок команда завершается с кодом `1`, поэтому проверку можно встроить в CI.

Одни только предупреждения (`warning`) код выхода не меняют: при `Errors: 0` команда завершается с кодом `0`.

Полный список флагов `scan` — на странице [Команды и флаги](/ru/cli/commands/).

## 4. Исправьте нарушение и запустите снова

Переименуйте папку вместе с файлом внутри неё:

```
src/
└── components/
    └── Icon/
        ├── Icon.tsx
        └── index.ts
```

и повторите команду сканирования:

```text
Errors: 0, warnings: 0.

✔ Validation complete successfully!
```

Проверка прошла: структура соответствует конфигу, а следующее такое нарушение будет поймано ещё до ревью.

## 5. Закрепите проверку в команде

Добавьте скрипт в `package.json`:

```json
{
  "scripts": {
    "lint:tree": "tree-lint scan"
  }
}
```

Теперь локально можно запускать `npm run lint:tree`, `pnpm lint:tree` или `yarn lint:tree`.

В CI достаточно вызвать тот же скрипт — шаг упадёт при первой ошибке:

```yaml
- name: Lint file structure
  run: pnpm lint:tree
```

Тот же вызов подходит для pre-commit хука:

```bash
# .husky/pre-commit
pnpm lint:tree
```

Подробнее о встраивании проверки в CI и git-хуки — на странице [Интеграция с CI/CD](/ru/cli/ci-cd/).

## Создание конфига через `init`

Вместо файла вручную можно сгенерировать шаблон конфига командой:

```bash
tree-lint init
```

Команда создаёт файл `tree-lint.config` в текущем каталоге. Поддерживается интерактивный и неинтерактивный режим.

**Интерактивный режим** (TTY-терминал вне CI) - команда запросит недостающие параметры через prompt и предложит подтверждение перед созданием файла. Если выбор не устраивает, можно вернуться и указать параметры заново.

**Неинтерактивный режим** (CI) - все параметры должны быть переданы явно через флаги:

```bash
tree-lint init --format ts --type deep-tree
```

Полный список флагов `init` и доступные шаблоны — на странице [Команды и флаги](/ru/cli/commands/).
