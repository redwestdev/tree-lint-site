Tree-lint сверяет структуру папок и файлов с вашими правилами — за миллисекунды и без разбора содержимого кода. Ниже — короткий путь от установки до первой исправленной ошибки и проверки в CI.

## 1. Установите пакет

<Tabs syncKey='pkg'>
  <TabItem label='npm'>

```bash
npm install -D @redwestdev/tree-lint
```

  </TabItem>
  <TabItem label='pnpm'>

```bash
pnpm add -D @redwestdev/tree-lint
```

  </TabItem>
  <TabItem label='yarn'>

```bash
yarn add -D @redwestdev/tree-lint
```

  </TabItem>
</Tabs>

Для работы Tree-lint требуется [Node.js](https://nodejs.org/) версии 18 или выше. Пакет устанавливается как dev-зависимость и добавляет команду `tree-lint` в `node_modules/.bin`.

Локально команда доступна тремя способами: внутри скриптов `package.json` (менеджер пакетов сам добавляет локальный `node_modules/.bin` в `PATH`), через `npx tree-lint`, `pnpm exec tree-lint` или `yarn tree-lint`. Проще всего сразу завести скрипт `"lint:tree": "tree-lint scan"` — он же пригодится в CI на шаге 4.

## 2. Создайте конфиг под свой стек

Конфиг не нужно писать вручную — сгенерируйте основу одной командой:

```bash
npx tree-lint init
```

Генератор спросит формат (`ts`, `js`, `json`, `yaml`) и тип шаблона (`default` или `deep-tree`) и создаст файл конфига в текущем каталоге. Дальше достаточно подставить правила под свою архитектуру.

### Выберите свою архитектуру

Описывайте только те папки, за которыми хотите следить: всё остальное tree-lint пропускает. Ниже — пример для React-хуков: дерево слева, конфиг справа.

Импорт во всех примерах одинаковый — дальше не повторяем:

```ts
import { createConfig } from '@redwestdev/tree-lint';
```

**Задача.** Хуки всегда в camelCase — иначе ошибка; слишком длинное имя — предупреждение. Хук распознаётся только по приставке `use`, формат файла не важен.

<Tabs syncKey='stack'>
  <TabItem label='React.js'>
    Хук — это файл, имя которого начинается с `use`. `useCounter.ts` дерево проходит, `use_foo.ts` ловит ошибку, а `useThisHookNameIsDefinitelyTooLong.ts` — предупреждение.

    <ArchSplit>
      <Fragment slot='tree'>

```tree
src/
├── hooks/
│   ├── useCounter.ts
│   ├── use_foo.ts
│   └── useThisHookNameIsDefinitelyTooLong.ts
└── utils/
    └── useSettings.ts
```

      </Fragment>
      <Fragment slot='config'>

```ts title="tree-lint.config.ts"
export default createConfig({
  roots: ['src'],

  entities: {
    hook: {
      matches: { type: 'file', name: 'use*' },
      rules: {
        name: {
          type: 'error',
          pattern: 'use[A-Z]*',
          message: 'Хук: use + camelCase.',
        },
        nameLength: { type: 'warning', max: 30 },
      },
    },
  },

  layers: {
    hooks: { entities: ['hook'] },
  },
});
```

      </Fragment>
    </ArchSplit>

    Что за что отвечает:

    - `matches` — как распознаётся сущность. Маска — синтаксис micromatch и применяется к полному имени файла: `use*` означает «начинается с `use`» и не ограничивает расширение — подойдёт и `useCounter.ts`, и `useCounter.js`.
    - `rules.name` — формат имени распознанных файлов: маска `use[A-Z]*` требует после `use` заглавную букву, то есть camelCase. `use_foo.ts` её не проходит и падает ошибкой с текстом из `message`.
    - `rules.nameLength` — предел длины имени: длиннее 30 символов — предупреждение. У файлов длина считается вместе с расширением: `useThisHookNameIsDefinitelyTooLong.ts` — 37 символов.
    - `layers` — папки по точному имени и сущности, которые в них ищутся: `hooks` — только `hook`. Сущности распознаются только внутри слоёв, поэтому `src/utils/useSettings.ts` не проверяется — он лежит вне `hooks`, хотя имя и начинается с `use`.

  </TabItem>
</Tabs>

Предупреждения (`⚠`) печатаются, но код выхода не меняют: сборку роняет только ошибка — так правила можно вводить постепенно.

Подробнее про правила — на странице [Валидация сущности](/ru/validation/entities/), про концепцию — в [Вступлении](/ru/concepts/intro/).

## 3. Запустите сканирование и исправьте первую ошибку

<Tabs syncKey='pkg'>
  <TabItem label='npm'>

```bash
npx tree-lint scan
```

  </TabItem>
  <TabItem label='pnpm'>

```bash
pnpm exec tree-lint scan
```

  </TabItem>
  <TabItem label='yarn'>

```bash
yarn tree-lint scan
```

  </TabItem>
</Tabs>

Вернёмся к дереву из шага 2: `use_foo.ts` нарушает camelCase, а имя `useThisHookNameIsDefinitelyTooLong.ts` не укладывается в 30 символов. Первый запуск:

<Tabs syncKey='stack'>
  <TabItem label='React.js'>

```text
src/hooks/useThisHookNameIsDefinitelyTooLong.ts
  ⚠ Name length is outside the allowed character limits

src/hooks/use_foo.ts
  ✖ Хук: use + camelCase.

Errors: 1, warnings: 1.

✖ Validation failed.
```

  </TabItem>
</Tabs>

Текст предупреждения у встроенного `nameLength` фиксированный — поэтому на английском; у ошибки сообщение своё, из поля `message`. Ошибка `✖` завершает команду с кодом `1`. Переименуем `use_foo.ts` в `useFoo.ts` и запустим ещё раз:

<Tabs syncKey='stack'>
  <TabItem label='React.js'>

```text
src/hooks/useThisHookNameIsDefinitelyTooLong.ts
  ⚠ Name length is outside the allowed character limits

Errors: 0, warnings: 1.

✔ Validation complete successfully!
```

  </TabItem>
</Tabs>

Ошибка ушла — и команда вернула код `0`, хотя предупреждение осталось: длинное имя можно сократить позже. На коде выхода и строится проверка в CI. Все флаги `scan` — на странице [Команды и флаги](/ru/cli/commands/).

## 4. Закрепите проверку в проекте

Добавьте скрипт в `package.json`:

```json
{
  "scripts": {
    "lint:tree": "tree-lint scan"
  }
}
```

Тот же вызов подойдёт и для pre-commit хука, и для шага CI:

```yaml
- name: Lint file structure
  run: pnpm lint:tree
```
