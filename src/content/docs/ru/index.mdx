## Одна проблема — от соглашения до исправления

Команда договорилась: компонент — это папка с файлом `*.tsx` и `index.ts`, а имя папки не длиннее 20 символов.

```text
src/
└── components/
    └── VeryLongComponentName/   ← 22 символа
        ├── VeryLongComponentName.tsx
        └── index.ts
```

Соглашение записано в конфиге:

```ts
entities: {
  component: {
    matches: {
      type: "directory",
      name: "[A-Z]*",
      children: [
        { type: "file", name: "*.tsx" },
        { type: "file", name: "index.ts" },
      ],
    },
    rules: {
      nameLength: {
        type: "error",
        max: 20,
        message: "Имя папки компонента слишком длинное: уложитесь в 20 символов.",
      },
    },
  },
},
```

Запуск `tree-lint scan` находит нарушение и показывает ваше собственное сообщение:

```text
src/components/VeryLongComponentName
  ✖ Имя папки компонента слишком длинное: уложитесь в 20 символов.

Errors: 1, warnings: 0.
```

После переименования в `Icon` та же команда завершается успехом:

```text
Errors: 0, warnings: 0.

✔ Validation complete successfully!
```

С этого момента соглашение проверяется при каждом запуске — локально и в CI, одинаково для всех. Полный сценарий с деревом проекта, командами установки и пояснением каждой секции конфига — в [Быстром старте](/ru/getting-started/quick-start/).

## Как начать

1. Установите пакет как dev-зависимость: `npm install -D @redwestdev/tree-lint` (или `pnpm add -D`, `yarn add -D`).
2. Опишите в `tree-lint.config.ts` небольшую область: одну сущность и одно правило.
3. Запустите `npx tree-lint scan` и исправьте найденное.

Подробности — на странице [Быстрый старт](/ru/getting-started/quick-start/).

## Границы и ответы на сомнения

- **Нужно ли менять архитектуру?** Нет. Конфиг описывает существующую структуру, а правила применяются только к тому, что вы описали.
- **Заменяет ли Tree-lint линтер исходного кода?** Нет. Проверяются имена файлов и папок, их состав и заданные ограничения — не содержимое кода и не импорты.
- **Обязательно ли проверять весь проект?** Нет. `roots` и `ignore` ограничивают область, а начать можно с предупреждений вместо ошибок.
- **Что даёт конфиг при работе с ИИ?** Ассистент может прочитать те же правила, а результат его работы проверяется тем же запуском, что и ваш код.
