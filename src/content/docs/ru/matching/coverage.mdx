---
title: Как покрыть проект
description: 'Рекомендации по порядку описания проекта в конфиге: от листьев-сущностей к слоям и группам.'
---

Покрывать весь проект сразу не стоит. Конфиг, написанный за один подход, трудно проверять: ошибка в `matches` не выдаёт ошибку — узел просто не распознаётся, и найти, где именно вы промахнулись, становится сложно. Надёжнее идти **от листьев к слоям**: сначала описать самые мелкие единицы структуры, а уже потом их объединения.

## Три шага

1. **Листья — сущности.** Начните с одной-двух сущностей: самых мелких и однозначных единиц структуры. Хорошая сущность описывается одним предложением и уверенно определяется по имени.
2. **Появилось несколько сущностей — объединяйте их в слой.** Как только однотипных сущностей стало больше одной, им нужен слой — папка, внутри которой они ищутся.
3. **Сущностей в слое слишком много — фасуйте по папкам и объявляйте группой.** Разросшийся слой разбивается на подпапки, и каждая такая папка описывается группой, а не новой сущностью.

## Пример: проект растёт вместе с конфигом

### Шаг 1. Одна сущность

В проекте есть папка с хуками — начнём с неё. Сущность ищется только внутри слоя, поэтому минимальная пара — сущность и слой с её именем:

```ts
entities: {
  hook: {
    matches: { type: 'file', name: 'use[A-Z]*.ts' },
  },
},

layers: {
  hooks: { entities: ['hook'] },
},
```

Такой конфиг уже проверяет все файлы `use*.ts` внутри папок `hooks`.

### Шаг 2. Сущностей стало несколько — появляется слой

Рядом появились компоненты, секции и страницы. Каждая из них — отдельная сущность, а объединяет их слой `components`:

```ts
entities: {
  hook: {
    matches: { type: 'file', name: 'use[A-Z]*.ts' },
  },
  component: {
    matches: {
      type: 'directory',
      name: '*Cmp',
      children: [{ type: 'file', name: 'index.ts' }],
    },
  },
  section: {
    matches: { type: 'directory', name: '*Sct' },
  },
  page: {
    matches: { type: 'directory', name: '*Pg' },
  },
},

layers: {
  hooks: { entities: ['hook'] },
  components: { entities: ['component', 'section', 'page'] },
},
```

Слой задаёт зону поиска: `page` распознаётся только внутри папок `components`, а не по всему проекту.

### Шаг 3. Сущностей в слое слишком много — фасуем по папкам

В слое `components` накопились десятки папок-страниц, и держать их одним списком неудобно. Раскладываем их по папкам-категориям, а сами категории описываем группой:

```
src/
└── components/
    ├── settings/
    │   ├── AccountPg/
    │   └── SecurityPg/
    └── profile/
        └── ProfilePg/
```

```ts
groups: {
  name: '[a-z]*',                                  // папка-категория: settings, profile
  children: [{ type: 'directory', name: '*Pg' }],  // внутри — папки-страницы
  rules: {
    nameLength: { type: 'warning', max: 20 },
  },
},
```

Группа отвечает на вопрос «что это за папка?» без объявления новой сущности и без привязки к слою: правила применяются к самой папке-категории. Новый вид папки внутри слоя — это всегда группа, а не ещё одна сущность.
