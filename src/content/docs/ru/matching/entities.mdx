**Сущность** — именованный тип узлов проекта. Tree-lint распознаёт узел как сущность по полю `matches`, а затем проверяет его правилами `rules`. Сущности объявляются в секции `entities` конфига:

```ts
entities: {
  component: {
    matches: {
      type: 'directory',
      name: '[A-Z]*',
      children: [
        { type: 'file', name: '*.tsx' },
        { type: 'file', name: 'index.ts' },
      ],
    },
    rules: {
      nameLength: { type: 'error', max: 20 },
    },
  },
},
```

Общий обзор понятий — на странице [Сущности](/ru/concepts/entities/).

## Как работает `matches`

- `type` — `"file"` или `"directory"`: к какому виду узлов применяется сущность.
- `name` — micromatch-глоб для имени узла. Для файлов сопоставляется полное имя вместе с расширением.
- `children` — только для директорий: **обязательный состав**. Каждый перечисленный матчер должен найти себе отдельный дочерний элемент; лишние файлы и папки совпадению не мешают.

Сущность распознана, только если **все** матчеры совпали. Правила `rules` применяются только к распознанным сущностям.

## Рекомендация: определяйте сущность по названию

Самое простое и надёжное определение сущности — **по названию**. Если имя узла уже говорит, что это за сущность, никаких дополнительных условий не нужно: правило распознавания остаётся коротким, а вся команда понимает его без объяснений.

Проще всего работают маркеры в названии — устойчивые приставки и окончания:

| Маркер     | Сущность   | Пример            |
| ---------- | ---------- | ----------------- |
| `Cmp`      | компонент  | `ButtonCmp/`      |
| `Pg`       | страница   | `HomePg/`         |
| `Sct`      | секция     | `HeroSct/`        |
| `use`      | хук        | `useCounter.ts`   |
| `Fn`       | функция    | `formatDateFn.ts` |
| `Route`    | роут       | `userRoute.ts`    |
| `.test.ts` | файл теста | `Button.test.ts`  |
| `Util`     | утилита    | `dateUtil.ts`     |

Такому названию хватает одного матчера:

```ts
entities: {
  component: {
    matches: { type: 'directory', name: '*Cmp' },
  },
},
```

Порядок, в котором стоит описывать сущности, разобран на странице [Как покрыть проект](/ru/matching/coverage/).

## Почему правило «не сработало»

Распознавание всегда идёт раньше проверки. Если папка не совпала с `matches`, правила `rules` этой сущности к ней не применяются — в том числе `rules.name`. Поэтому:

- не задавайте в `matches.name` тот же глоб, что и в `rules.name.pattern`: правило просто продублирует уже пройденную проверку. Отдельное правило полезно, когда оно строже распознавания — например, `matches.name: "[A-Z]*"` распознаёт папку, а `rules.name.pattern: "[A-Z][a-z]*"` требует имя из букв;
- если нужно проверить папку, которая не проходит `matches`, ослабьте `matches` или воспользуйтесь [группами](/ru/matching/groups/).

## Вложенные сущности

Сущность-директория может объявить собственные вложенные сущности через поле `entities`:

```ts
entities: {
  page: {
    matches: { type: "directory", name: "[A-Z]*" },
    entities: ["section"], // внутри каждой страницы ищутся сущности "section"
  },

  section: {
    matches: {
      type: "directory",
      name: "[A-Z]*Sct",
      children: [{ type: "file", name: "index.ts" }],
    },
  },
},
```

Вложенные сущности распознаются только внутри той сущности, которая их объявила, — даже если они не перечислены ни в одном слое.

## Примечания

Определение по названию — базовый и пока основной способ. Методы определения сущностей планируется пополнять более сложными и тонкими вещами; как минимум в планах:

- определение по содержимому файлов сущности;
- определение по флагу внутри файла сущности.
