title: Определение слоя
description: 'Как Tree-lint распознаёт слой: точное совпадение имени папки с ключом секции layers.'
---

**Слой** — папка, имя которой **точно** совпадает с ключом секции `layers`. Глобы в именах слоёв не поддерживаются, регистр важен: ключ `components` распознает только папку `components`, но не `Components`.

## Где ищутся слои

- слои распознаются на **любой глубине** внутри `roots` — не только на первом уровне;
- имя папки сравнивается с ключом слоя без учёта пути: папка `src/features/button/components` — это тот же слой `components`, что и `src/components`;
- папка, которая уже распознана как сущность, не рассматривается как слой.

```ts
roots: ["src"],

layers: {
  components: {
    entities: ["component"],
  },
},
```

Такая конфигурация распознает папки `components` и в `src/components`, и в `src/features/button/components`.

## Как слои связывают сущности и папки

Сущности ищутся **только внутри слоёв** (или внутри другой сущности — см. [вложенные сущности](/ru/matching/entities/#вложенные-сущности)). Сущность, не перечисленная ни в одном слое, не будет распознана нигде. Если сослаться на необъявленную сущность, конфиг будет отклонён с ошибкой.

Слой ограничивает зону действия сущности: `hooks: { entities: ["hook"] }` означает, что хуки распознаются только внутри папок с именем `hooks` внутри `roots`.

## Правила для самого слоя

Слой — это обычная папка, поэтому для него можно задать собственные `rules` — они применяются к самой папке-слою. Список доступных правил — на странице [Валидация слоя](/ru/validation/layers/).
