description: 'Как описать правила для файлов и папок в конфиге Tree-lint.'
---

Блок `rules` описывает проверки и всегда вкладывается в конкретное место конфига: в сущность, слой, группу или в запись `_matches` для дочерних элементов. Здесь показаны два полных блока — для сущности-файла и для сущности-папки; подставьте их в `rules` своей сущности.

Общие для всех правил поля:

- **`type`** — уровень нарушения: `"error"` или `"warning"`. Только ошибки приводят к ненулевому коду выхода `tree-lint scan`.
- **`message`** — необязательный текст, который заменяет стандартное сообщение о нарушении в отчёте.
- **`min` / `max`** — числовые границы. У числовых правил `min` по умолчанию равен `1`; у `max` нет значения по умолчанию, и его нужно указывать явно — иначе правило всегда падает.
- Границы **`size`** задаются в **килобайтах**.
- **`name.pattern`** — glob-паттерн [micromatch](https://github.com/micromatch/micromatch), который применяется к полному имени (включая расширение). Это не регулярное выражение: используйте glob-синтаксис, например `+([a-z0-9-])` вместо `^[a-z0-9-]+$`.

## Правила для сущности-файла

Для файлов доступны `name`, `nameLength`, `size`, `lineCount`, `isEmpty` и `custom`. Пример для сущности `util` — TypeScript-файла в слое `utils`:

```ts
export default createConfig({
  entities: {
    util: {
      matches: { type: 'file', name: '*.ts' },
      rules: {
        name: {
          pattern: '+([a-z0-9-])',
          type: 'error',
          message: 'Имя должно содержать только строчные буквы, цифры и дефисы',
        },
        nameLength: {
          min: 3,
          max: 20,
          type: 'warning',
        },
        size: {
          max: 100,
          type: 'error',
        },
        lineCount: {
          max: 200,
          type: 'error',
        },
        isEmpty: {
          type: 'error',
        },
      },
    },
  },
  layers: {
    utils: { entities: ['util'] },
  },
});
```

У `nameLength` и `size` здесь обе границы (`min` опущен у `size` — действует значение по умолчанию `1`), а у `lineCount` задан только `max`.

## Правила для сущности-папки

Для папок доступны `name`, `nameLength`, `size`, `childrenAmount`, `isEmpty` и `custom`. Пример для сущности `component` из [Быстрого старта](/ru/getting-started/quick-start/):

```ts
export default createConfig({
  entities: {
    component: {
      matches: {
        type: 'directory',
        name: '[A-Z]*',
        children: [
          { type: 'file', name: '*.tsx' },
          { type: 'file', name: 'index.ts' },
        ],
      },
      rules: {
        nameLength: {
          max: 20,
          type: 'error',
          message:
            'Имя папки компонента слишком длинное: уложитесь в 20 символов.',
        },
        childrenAmount: {
          max: 10,
          type: 'warning',
        },
        isEmpty: {
          type: 'error',
        },
      },
    },
  },
  layers: {
    components: { entities: ['component'] },
  },
});
```

Проверки из этого блока применяются к самой папке: `nameLength` — к её имени, `childrenAmount` — к числу прямых дочерних элементов, `isEmpty` — к суммарному размеру содержимого.

Подробнее о том, как измеряется каждое правило, — на странице [Правила валидации](/ru/rules/).
