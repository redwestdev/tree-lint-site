---
title: Использование проверки custom
description: 'Сигнатура функции обратного вызова, структура результата проверки и примеры custom().'
---

`custom` — обычное правило, которое объявляется в блоке `rules` сущности, слоя, группы или записи `_matches` для дочерних элементов. Вместо фиксированной логики правило вызывает вашу функцию, которая сама решает, пройдена проверка или нет. Доступно только в конфигах `.ts` и `.js`.

## Сигнатура функции обратного вызова

```typescript
callback: (
  node: Node,
  results?: Partial<Record<string, IValidationResult>>[]
) => boolean;
```

Тип `node` зависит от места объявления правила:

| Место объявления `custom`                       | Тип `node` в функции                                   |
| ----------------------------------------------- | ------------------------------------------------------ |
| `entities.*.rules`, `matches.type: "file"`      | `FileEntity`                                           |
| `entities.*.rules`, `matches.type: "directory"` | `DirEntity`                                            |
| `layers.*.rules`                                | `LayerNode`                                            |
| `groups.rules`                                  | `GroupNode`                                            |
| `rules.children[]` с `_matches`                 | `FileNode` или `DirNode` — по типу совпавшего элемента |

Поля каждого типа — на странице [Поля node](/ru/rules/node-fields/).

- В правиле **обязательно указывать `type`**. Без него Tree-lint 0.0.5 завершается внутренней ошибкой: `Cannot read properties of undefined (reading 'push')`.
- Функция **обязана возвращать boolean**. Любое другое значение (включая `undefined`, если нет `return`) считается нарушением: "Custom rule must return a boolean, but returned &lt;type&gt;".
- `results` — результаты предопределённых проверок (`name`, `nameLength`, `size`, `isEmpty`) для данного узла: массив с одним объектом вида `{ [ruleName]: IValidationResult }`.
- В `results` попадают только те проверки, для которых в конфиге явно указаны параметры. Проверки `lineCount`, `childrenAmount` и `custom` туда **не входят**.
- Параметр `message` заменяет стандартный текст нарушения в отчёте.

## Структура `IValidationResult`

Схема для справки — это тип из пакета, а не исполняемый код:

```typescript
interface IValidationResult {
  result: boolean; // true, если проверка пройдена
  violation?: {
    // Данные об ошибке, если проверка не пройдена
    type: 'error' | 'warning';
    path: string;
    message: string;
  };
}
```

## Примеры

### Проверка файла-сущности

`custom` объявлен в сущности-файле, поэтому `node` — это `FileEntity`: доступны `extension` и `lines`. Полный конфиг:

```ts
import { createConfig } from '@redwestdev/tree-lint';

export default createConfig({
  entities: {
    util: {
      matches: { type: 'file', name: '*.ts' },
      rules: {
        custom: {
          type: 'error',
          message: 'Файл утилиты не должен быть пустым',
          callback: (node) => {
            // node: FileEntity
            return node.lines > 0;
          },
        },
      },
    },
  },
  layers: {
    utils: { entities: ['util'] },
  },
});
```

### Проверка папки-сущности

Здесь `node` — это `DirEntity`: доступны `children` и `entity`. Правило ограничивает число дочерних элементов папки компонента:

```ts
export default createConfig({
  entities: {
    component: {
      matches: {
        type: 'directory',
        name: '[A-Z]*',
        children: [{ type: 'file', name: '*.tsx' }],
      },
      rules: {
        custom: {
          type: 'warning',
          callback: (node) => {
            // node: DirEntity
            return node.children.length <= 20;
          },
        },
      },
    },
  },
  layers: {
    components: { entities: ['component'] },
  },
});
```

### Пример с использованием `results`

`results` удобно использовать, когда `custom` должен учесть итоги предопределённых правил. В конфиге ниже заданы `name` и `nameLength`, поэтому оба попадают в `results`:

```ts
export default createConfig({
  entities: {
    util: {
      matches: { type: 'file', name: '*.ts' },
      rules: {
        name: { type: 'warning', pattern: '+([a-z0-9-])' },
        nameLength: { type: 'warning', min: 3, max: 30 },
        custom: {
          type: 'error',
          message: 'Не пройдена ни одна проверка имени',
          callback: (node, results) => {
            // Если других правил нет — пропускаем
            if (!results || results.length === 0) return true;

            // results — массив из одного объекта { name: ..., nameLength: ... }
            const hasPassed = results.some((ruleResult) =>
              Object.values(ruleResult).some((res) => res.result === true)
            );

            // false, только если ВСЕ проверки провалены
            return hasPassed;
          },
        },
      },
    },
  },
  layers: {
    utils: { entities: ['util'] },
  },
});
```
