## Что такое `rules`

`rules` — это секция конфигурации Tree-lint, которая описывает **проверки**, применяемые к узлам дерева проекта (файлам, папкам, сущностям и слоям). Каждое правило отвечает на один конкретный вопрос: правильное ли имя у файла, не слишком ли он большой, не пустая ли папка и так далее.

Правила не существуют сами по себе — они привязаны к месту, где объявлены. Задать `rules` можно в четырёх местах:

- **в сущности** (`entities.*.rules`) — применяются к каждой совпавшей сущности;
- **в слое** (`layers.*.rules`) — применяются к самой папке-слою;
- **в группе** (`groups.rules`) — применяются к папкам, совпавшим с группой;
- **для дочерних элементов** (`rules.children[]` с `_matches`) — применяются к дочерним элементам, совпавшим с паттерном, а не к самой сущности.

Подробнее о том, где и как объявляются эти секции, — в разделе [Концепции](/ru/getting-started/concepts/).

## Тип данных

`rules` — это обычный **объект** (в терминах TypeScript — `Record<string, RuleConfig>`), где:

- **ключ** — название правила (`name`, `size`, `custom` и т.д.);
- **значение** — объект с параметрами правила: границы (`min`/`max`), `pattern`, `type`, `message`, а для `custom()` — ещё и `callback`.

```ts
rules: {
  name: { type: "error", pattern: "[a-z]*" },  // ключ → объект параметров
  size: { type: "warning", max: 100 },
}
```

Уровень нарушения задаёт поле `type`: `"error"` приводит к ненулевому коду выхода `tree-lint scan`, а `"warning"` — только к предупреждению в отчёте. Текст нарушения можно переопределить полем `message`.

## Роль и кейсы

Роль `rules` — превратить декларативное описание архитектуры в исполняемые проверки: всё, что описано в `entities`, `layers` и `groups`, валидируется именно через правила из этих секций.

Доступные правила делятся на две группы:

- **Предопределённые** — готовые проверки с фиксированной логикой и простыми числовыми/строковыми параметрами. Работают в любом формате конфига (`.ts`, `.js`, `.json`, `.yaml`).
- **`custom()`** — произвольная проверка на основе функции обратного вызова, которая сама решает, пройдена проверка или нет. Доступна только в конфигах `.ts` и `.js`.

Полный список правил и их параметры — в таблице ниже.

| Правило          | Описание              | Параметры             | Применимо к |
| :--------------- | :-------------------- | :-------------------- | :---------- |
| `name`           | Именование (glob)     | `pattern` (string)    | Все         |
| `nameLength`     | Длина имени           | `min`, `max` (number) | Все         |
| `size`           | Размер                | `min`, `max` (number) | Все         |
| `lineCount`      | Кол-во строк          | `min`, `max` (number) | Файлы       |
| `childrenAmount` | Кол-во дочерних узлов | `min`, `max` (number) | Папки       |
| `isEmpty`        | Проверка пустоты      | —                     | Все         |
| `custom()`       | Произвольная проверка | `callback` (function) | Все         |

## Как измеряются правила

Несколько деталей, которые стоит знать до написания конфига:

- **`size`** — размер в **килобайтах** (KB), а не в байтах. Внутри `custom()` поле `node.size` содержит байты; разделите его на `1024`, чтобы сравнивать с этим правилом. `min` по умолчанию равен `1`; `max` обязателен — без него правило всегда падает.
- **`nameLength`** — количество символов полного имени. Для файлов учитывается и расширение: `Button.tsx` имеет длину `10`. `min` по умолчанию равен `1`; `max` обязателен.
- **`name`** — glob-паттерн [micromatch](https://github.com/micromatch/micromatch), который применяется к полному имени (для файлов — вместе с расширением). Паттерн обязателен: пустой паттерн всегда падает. Работают диапазоны в фигурных скобках, например `*.{ts,tsx}`.
- **`lineCount`** — количество строк в файле. `min` по умолчанию равен `1`; `max` обязателен.
- **`childrenAmount`** — количество прямых дочерних элементов папки. `min` по умолчанию равен `1`; `max` обязателен.
- **`isEmpty`** — размер узла равен `0`. Для папок размер — это сумма всех вложенных файлов, поэтому папка, содержащая только пустые файлы, считается «пустой».
- **`custom()`** — callback **обязан возвращать boolean**. Любое другое значение (включая `undefined`, если нет `return`) считается нарушением.
- **`message`** — любое правило принимает параметр `message`, который заменяет текст нарушения по умолчанию в отчёте сканирования. Удобно для пояснения собственных договорённостей.

Правила можно задавать не только на уровне сущности, но и для совпавших дочерних элементов (`_matches`) и для `groups` — см. [Концепции](/ru/getting-started/concepts/).
