## Одна проблема — від домовленості до виправлення

Команда домовилася: компонент — це папка з файлом `*.tsx` та `index.ts`, а ім'я папки не довше ніж 20 символів.

```text
src/
└── components/
    └── VeryLongComponentName/   ← 22 символи
        ├── VeryLongComponentName.tsx
        └── index.ts
```

Домовленість записана в конфігу:

```ts
entities: {
  component: {
    matches: {
      type: "directory",
      name: "[A-Z]*",
      children: [
        { type: "file", name: "*.tsx" },
        { type: "file", name: "index.ts" },
      ],
    },
    rules: {
      nameLength: {
        type: "error",
        max: 20,
        message: "Ім'я папки компонента задовге: вкладіться у 20 символів.",
      },
    },
  },
},
```

Запуск `tree-lint scan` знаходить порушення і показує ваше власне повідомлення:

```text
src/components/VeryLongComponentName
  ✖ Ім'я папки компонента задовге: вкладіться у 20 символів.

Errors: 1, warnings: 0.
```

Після перейменування на `Icon` та сама команда завершується успішно:

```text
Errors: 0, warnings: 0.

✔ Validation complete successfully!
```

Відтепер домовленість перевіряється під час кожного запуску — локально й у CI, однаково для всіх. Повний сценарій із деревом проєкту, командами встановлення і поясненням кожної секції конфіга — у [Швидкому старті](/uk/getting-started/quick-start/).

## Як почати

1. Встановіть пакет як dev-залежність: `npm install -D @redwestdev/tree-lint` (або `pnpm add -D`, `yarn add -D`).
2. Опишіть у `tree-lint.config.ts` невелику область: одну сутність і одне правило.
3. Запустіть `npx tree-lint scan` і виправте знайдене.

Подробиці — на сторінках [Встановлення](/uk/getting-started/installation/) та [Швидкий старт](/uk/getting-started/quick-start/).

## Межі та відповіді на сумніви

- **Чи потрібно змінювати архітектуру?** Ні. Конфіг описує наявну структуру, а правила застосовуються лише до того, що ви описали.
- **Чи замінює Tree-lint лінтер вихідного коду?** Ні. Перевіряються імена файлів і папок, їхній склад і задані обмеження — не вміст коду й не імпорти.
- **Чи обов'язково перевіряти весь проєкт?** Ні. `roots` та `ignore` обмежують область, а почати можна з попереджень замість помилок.
- **Що дає конфіг під час роботи з ШІ?** Асистент може прочитати ті самі правила, а результат його роботи перевіряється тим самим запуском, що й ваш код.
