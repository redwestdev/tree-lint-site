## Що таке `rules`

`rules` — це секція конфіга Tree-lint, яка описує **перевірки**, що застосовуються до вузлів дерева проєкту (файлів, папок, сутностей і шарів). Кожне правило відповідає на одне конкретне запитання: чи правильне ім'я файла, чи не завеликий він, чи не порожня папка тощо.

Правила не існують самі по собі — вони прив'язані до місця, де оголошені. Задати `rules` можна у чотирьох місцях:

- **у сутності** (`entities.*.rules`) — застосовуються до кожної розпізнаної сутності;
- **у шарі** (`layers.*.rules`) — застосовуються до самої папки шару;
- **у групі** (`groups.rules`) — застосовуються до папок, що збіглися з групою;
- **для дочірніх елементів** (`rules.children[]` з `_matches`) — застосовуються до дочірніх елементів, що збіглися з патерном, а не до самої сутності.

Де і як оголошуються ці секції — у [Концепціях](/uk/getting-started/concepts/).

## Тип даних

`rules` — це звичайний **об'єкт** (у термінах TypeScript — `Record<string, RuleConfig>`), де:

- **ключ** — назва правила (`name`, `size`, `custom` тощо);
- **значення** — об'єкт із параметрами правила: ліміти (`min`/`max`), `pattern`, `type`, `message`, а для `custom()` ще й `callback`.

```ts
rules: {
  name: { type: "error", pattern: "[a-z]*" },  // ключ → об'єкт параметрів
  size: { type: "warning", max: 100 },
}
```

Рівень порушення задається полем `type`: `"error"` веде до ненульового коду виходу `tree-lint scan`, а `"warning"` лише додає попередження у звіт. Текст порушення можна перевизначити полем `message`.

## Роль і сценарії використання

Роль `rules` — перетворити декларативний опис архітектури на виконувані перевірки: усе, що описано в `entities`, `layers` і `groups`, перевіряється саме правилами з цих секцій.

Доступні правила діляться на дві групи:

- **Вбудовані** — готові перевірки з фіксованою логікою та простими числовими або рядковими параметрами. Працюють у будь-якому форматі конфіга (`.ts`, `.js`, `.json`, `.yaml`).
- **`custom()`** — довільна перевірка на основі функції-колбека, яка сама вирішує, чи пройдено перевірку. Доступна лише в конфігах `.ts` та `.js`.

Повний список правил та їхніх параметрів — у таблиці нижче.

| Правило          | Опис                      | Параметри            | Застосовується до |
| :--------------- | :------------------------ | :------------------- | :---------------- |
| `name`           | Найменування (глоб)       | `pattern` (рядок)    | Усі               |
| `nameLength`     | Довжина імені             | `min`, `max` (числа) | Усі               |
| `size`           | Розмір                    | `min`, `max` (числа) | Усі               |
| `lineCount`      | Кількість рядків          | `min`, `max` (числа) | Файли             |
| `childrenAmount` | Кількість дочірніх вузлів | `min`, `max` (числа) | Папки             |
| `isEmpty`        | Перевірка на порожнечу    | —                    | Усі               |
| `custom()`       | Власна перевірка          | `callback` (функція) | Усі               |

## Як вимірюються правила

Кілька деталей, які варто знати перед написанням конфіга:

- **`size`** — розмір у **кілобайтах** (КБ), а не в байтах. Усередині `custom()` поле `node.size` містить байти; щоб порівняти з цим правилом, поділіть його на `1024`. `min` за замовчуванням — `1`; `max` обов'язковий — без нього правило завжди падає.
- **`nameLength`** — кількість символів у повному імені. Для файлів розширення теж рахується: `Button.tsx` має довжину `10`. `min` за замовчуванням — `1`; `max` обов'язковий.
- **`name`** — глоб-патерн [micromatch](https://github.com/micromatch/micromatch), що застосовується до повного імені (для файлів — разом із розширенням). Патерн обов'язковий: порожній патерн завжди падає. Працюють діапазони у фігурних дужках, наприклад `*.{ts,tsx}`.
- **`lineCount`** — кількість рядків у файлі. `min` за замовчуванням — `1`; `max` обов'язковий.
- **`childrenAmount`** — кількість прямих дочірніх елементів папки. `min` за замовчуванням — `1`; `max` обов'язковий.
- **`isEmpty`** — розмір вузла дорівнює `0`. Для папок розмір — це сума всіх вкладених файлів, тож папка, що містить лише порожні файли, вважається «порожньою».
- **`custom()`** — колбек **має повертати булеве значення**. Будь-яке інше (включно з `undefined`, коли немає `return`) зараховується як порушення.
- **`message`** — будь-яке правило приймає параметр `message`, який замінює стандартний текст порушення у звіті сканування. Зручно пояснювати власні домовленості.

Правила можна задавати не лише на рівні сутності, а й для дочірніх елементів за збігом (`_matches`) та для `groups` — див. [Концепції](/uk/getting-started/concepts/).
